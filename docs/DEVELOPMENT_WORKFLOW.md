# Рабочий процесс разработки JARVIS-OS

JARVIS-OS нужен контролируемый процесс разработки, потому что проект должен оставаться рабочим ассистентом, а не случайным набором файлов. Каждая новая задача должна быть понятной, ограниченной и проверяемой пользователем.

## Роли

- ChatGPT — архитектор проекта и планировщик задач.
- Пользователь — владелец проекта и финальный контролер.
- Codex — помощник по реализации утвержденных технических задач.

## Утвержденный процесс

ChatGPT plans -> User approves -> Codex executes -> User verifies -> Commit

1. ChatGPT готовит план и строгую задачу.
2. Пользователь проверяет задачу и утверждает ее.
3. Codex выполняет только утвержденную техническую задачу.
4. Пользователь вручную проверяет результат.
5. Commit выполняется только после успешной проверки.

## Почему задачи должны быть маленькими

Маленькие задачи проще проверить, проще откатить и проще понять. Они уменьшают риск случайно сломать существующее поведение JARVIS-OS. Если изменение большое, его нужно разделить на несколько независимых этапов.

## Проверка после каждой задачи

После каждой задачи JARVIS-OS должен проходить health check и тесты. Это подтверждает, что проект все еще запускается, основные папки на месте, зависимости доступны, а существующее поведение не сломано.

Рекомендуемые команды:

```powershell
.\scripts\health_check.ps1
pytest
```

## Если что-то сломалось

Если JARVIS-OS не запускается, тесты падают или результат задачи не совпадает с ожиданием, commit делать нельзя. Нужно остановиться, определить сломанный участок, исправить проблему в рамках отдельной утвержденной задачи или откатить последнее изменение по заранее описанному rollback plan.

## Ограничения для Codex

Codex не должен самостоятельно принимать архитектурные решения. Если задача требует изменения архитектуры, удаления существующей функции или изменения основного поведения, Codex должен остановиться и передать решение пользователю.

Codex должен сохранять JARVIS-OS как рабочего ассистента. Проект не должен превращаться в случайный набор файлов, временных экспериментов или несвязанных модулей.
