# TASK-009 — Local Memory Foundation

## Роль Codex

Ты инженер-исполнитель проекта JARVIS OS.

Архитектурные решения не принимаешь самостоятельно.
Работаешь строго по задаче.

## Главный архитектурный принцип

JARVIS OS должен всегда оставаться расширяемой платформой.

Память должна быть построена так, чтобы в будущем можно было добавить:

- краткосрочную память;
- долгосрочную память;
- память проектов;
- память рабочих процессов;
- голосовую память;
- память экранного контекста;
- semantic memory;
- vector search;
- локальные embeddings;
- синхронизацию только по разрешению пользователя.

Любое изменение должно сохранять модульность проекта.

## Цель

Добавить Local Memory Foundation — базовую локальную память JARVIS.

На этом этапе JARVIS должен уметь:

- сохранять простые заметки/факты локально;
- показывать сохранённые элементы памяти;
- считать количество элементов памяти;
- не отправлять память в интернет;
- не использовать внешние библиотеки;
- не сохранять память в GitHub;
- быть готовым к будущей семантической памяти.

## Приватность

Память пользователя должна храниться только локально.

Нельзя:

- отправлять память в интернет;
- использовать облако;
- использовать внешние API;
- сохранять память в GitHub;
- собирать данные без явной команды пользователя;
- автоматически запоминать всё подряд.

В этой задаче память сохраняется только после явной команды пользователя:

- запомни ...
- сохрани в память ...
- запомни что ...

## Нужно реализовать

### 1. LocalMemoryManager

Создать или обновить файл:

memory/memory_manager.py

В нём создать класс:

LocalMemoryManager

Он должен уметь:

- создавать локальное хранилище памяти;
- проверять, существует ли файл памяти;
- загружать память;
- сохранять память;
- добавлять новый элемент памяти;
- возвращать список элементов памяти;
- возвращать количество элементов памяти;
- искать элементы памяти простым текстовым поиском;
- работать без внешних библиотек.

Использовать только стандартные библиотеки Python:

- json
- pathlib
- datetime
- uuid

### 2. Файл хранения памяти

Память должна храниться локально в:

memory/local/memory.json

Если файла нет — создать автоматически.

Структура файла:

{
  "version": "0.1",
  "items": [
    {
      "id": "...",
      "type": "note",
      "content": "...",
      "source": "user_command",
      "tags": [],
      "created_at": "...",
      "updated_at": "..."
    }
  ]
}

### 3. Добавление элемента памяти

LocalMemoryManager должен иметь метод:

add_memory(content, memory_type="note", source="user_command", tags=None)

Он должен возвращать созданный элемент памяти.

Если content пустой — должна быть понятная ошибка ValueError.

### 4. Получение памяти

LocalMemoryManager должен иметь методы:

- list_memories()
- count_memories()
- search_memories(query)

Если памяти нет — возвращать пустой список.

### 5. DialogueManager

Добавить методы, если нужно:

- memory_saved_response(memory_content)
- memory_list_response(memories)
- no_memory_response()
- memory_search_response(memories, query)

Примеры:

Если память сохранена:

Исмаил, я запомнил: любишь зелёный цвет.

Если памяти нет:

Исмаил, пока в локальной памяти ничего нет.

Если память есть:

Исмаил, вот что я помню:
1. любишь зелёный цвет
2. используешь JARVIS для муниципальной работы

### 6. CommandProcessor integration

CommandProcessor должен понимать команды:

#### Добавление памяти

Команды:

- запомни
- запомни что
- сохрани в память
- сохрани это в память

Примеры:

запомни что я работаю с муниципальными письмами

запомни мой любимый цвет зелёный

сохрани в память что JARVIS должен видеть экран только с разрешения

Поведение:

- сохранить память через LocalMemoryManager;
- вернуть response через DialogueManager;
- intent: memory.add
- should_exit: false

#### Показать память

Команды:

- что ты помнишь
- покажи память
- моя память
- память

Поведение:

- показать список сохранённых элементов памяти;
- intent: memory.list
- should_exit: false

#### Поиск в памяти

Команды:

- найди в памяти
- поиск в памяти
- вспомни

Примеры:

найди в памяти цвет

вспомни муниципальные письма

Поведение:

- выполнить простой текстовый поиск по памяти;
- intent: memory.search
- should_exit: false

### 7. Безопасность памяти

Команды удаления памяти в этой задаче НЕ реализовывать.

Если пользователь пишет:

- забудь всё
- очисти память
- удали память

CommandProcessor должен передать это в SafeActionRouter или вернуть ответ, что удаление памяти требует отдельной подтверждаемой функции в будущем.

Нельзя удалять память в TASK-009.

### 8. Kernel integration

JARVISKernel должен создавать LocalMemoryManager как системный сервис.

Добавить сервис:

- memory_manager

Метод get_service("memory_manager") должен возвращать LocalMemoryManager.

Старые сервисы должны продолжить работать:

- logger
- event_bus
- module_manager
- command_processor
- action_router
- idea_manager

### 9. run.py

run.py должен передавать LocalMemoryManager или Kernel service в CommandProcessor так, чтобы команды памяти работали.

Простой интерактивный режим должен продолжить работать.

Нужно добавить в .gitignore:

memory/local/*.json

Но папка memory/local/ должна остаться в проекте.

Можно добавить:

memory/local/.gitkeep
